## 场景与范围

用户与触发：家庭经济困难的高职学生，在开学前后申报窗口进入系统。
前置条件：存在已发布的政策版本；任务已创建并锚定该版本。
结果产物：三档结论的项目清单 + 每项依据条款 + 材料清单 + 办理路径，可导出。
本次包含：政策入库与版本发布、条件原子化、确定性初判、依据条与材料清单、政策问答、复核与申诉留痕。
本次不包含：资格认定、资金发放、真实身份接入、县级政策口径、方言语音（二期）、批量工作台与看板（二期）、多校部署。

## 输入与输出契约

输入：`atom_code` 枚举值集合（详见 `docs/data-contract.md` 字段表）；允许部分缺失，缺失项不得推测。
输出：`{task_id, policy_version, items:[{project_id, project_name, conclusion, reasons:[{clause_id, policy_title, article_no, quote_span, effective_to}], materials:[...], channel:线上|线下}], disclaimer}`。
缺失处理：缺字段 → 该项 `need_check` 并指明缺哪一项；全部缺失 → 返回填写引导，不出结论。
时间口径：一律以 `policy_version` 的生效区间为准，不按当前系统时间推断政策有效性。

## 状态和规则

| 当前状态 | 动作／事件 | 条件 | 下一状态 | 持久化／副作用 | 失败处理 |
|---|---|---|---|---|---|
| draft | 提交情况 | 至少 1 个字段有值 | triaged | 写 task + items + event | 字段全空则拒绝并提示 |
| triaged | 提交复核 | 有辅导员账号权限 | pending_review | 写 review 记录 | 越权拒绝并写审计 |
| pending_review | 复核通过／驳回 | 复核人有权且条目存在 | reviewed | 写结论与理由 | 重复复核返回已有结果 |
| reviewed | 学生申诉 | 在申诉期内 | appealed | 写 appeal 记录，原结论保留 | 逾期拒绝并说明 |
| appealed | 人工改判 | 复核人确认 | amended | 原结论保留、新结论写入、导出件版本+1 | 无理由不得改判 |

不可违反的规则：I-1 无条款不出结论；I-2 不出"符合／不符合"；I-5 留痕不可删。
重复／并发／重试：同一任务重复提交返回已有结果（幂等）；并发复核以先写入为准，后写入者收到冲突提示，不得静默覆盖。
人工／模型／程序职责：判等=程序；文案与问答表达=模型；复核与改判=人工。

## 界面与接口影响

入口：单页勾选（分「家庭情况」「学籍情况」两组，可跳过）。
反馈：结论卡片显示三档标识、依据条（可点开原文）、材料清单、线下渠道；页面顶部恒显 `disclaimer`。
异常与恢复：无命中有专门空态；离线模式有角标；模式（真实／离线／Mock）在页脚标注。
接口：初判 `POST /api/triage`、任务查询 `GET /api/triage/{task_id}`、问答 `POST /api/qa`、复核 `POST /api/review`、导出 `GET /api/export/{task_id}`。字段以 `docs/data-contract.md` 为准。

## 示例

正常：全日制在读、广东户籍、家庭人均收入处于最低档、无其他资助 → 命中「国家助学金」「生源地信用助学贷款」，各附条款与材料清单。
异常：家庭人均收入未填 → 该项 `need_check`，仅输出可确定的项目，并提示补填后重算。
全部未命中（例如仅有校级临时补助在库而条件不符）→ 明示"当前版本未匹配"，给学校资助中心联系方式，不空手返回。

## 采集与切块实现（R-001／R-002 前置，已落地）

`tools/policy_collector.py` 走 HTTP 直连官方栏目页，不模拟点击网页：域名白名单、robots 检查、固定 3 秒间隔、单线程、条数上限、按内容哈希去重、原文快照落盘（`data/staging/raw/`）。
入库一律 `pending_verify`：文号只在页首 60 字或标题内认定，正文深处的文号视为引用他件不采用；缺失的施行日期保持待核；列表日期与落款日期相差超过 200 天时在 `note` 标"发文日期需核对"。
站点出现验证码、人机验证或"访问过于频繁"提示时立即停止并记录，不绕过。

- **多栏目批量**：`--preset 国家` 一次走综合政策、高校学生资助、中职、普通高中、义务教育、学前教育 6 个栏目；`--list A B C` 可指定任意多个栏目。
- **增量差集**：以详情页 URL 为键，已采条目不重复请求；`--limit` 限制的是"每栏新增数"，重复条目与附件页不占额度；`--force` 才会重取并比对内容哈希（变化则更新）。
- **条款切块**（`split`）：有"第X章／第X条"结构按条切，通知类按自然段切；`policy_clause` 每条带 `char_start/char_end`，`verify-clauses` 逐条校验能切回原文，作为 I-3 的机器可检形态。
- **草稿隔离**：`policy_staging.status=pending_verify`、`policy_clause.publishable=0`，文号与生效日期人工核对后才可进入发布流程（I-7）。

## 原子化实现（R-002 首批，3 份核心文件已抽取）

`tools/atomize.py` + `data/fields.json`（字段字典 v2，16 字段，D-009）+ `data/atoms/core3_atoms.json`（30 条原子）。

- **抽取范围**：只做首批 3 份——财教〔2021〕310号（国家层面资金办法与旧标准）、财教〔2024〕181号（标准调整）、粤财规〔2026〕1号（广东现行实施办法）；其余 16 份待首批结论验证后再摊。
- **覆盖项目**：本专科生国家助学金（GZ，10 条）、国家励志奖学金（LZ，5 条）、国家奖学金（GJ，5 条）、广东省家庭经济困难大学新生资助（XS，5 条）、校内学费减免（XN，4 条）、困难认定口径（DEF，1 条）。
- **五重校验**（导入时任一失败整批不写入）：字段在字典内、取值符合类型与枚举、`op` 在允许集内、`quote` 能在所属条款内定位、`body[quote_start:quote_end]` 与 `quote` 逐字一致。实测 30/30 通过。
- **判等边界**：`role=评审`（特别优秀／品学兼优）不参与自动判等，只提示需评审；`role=标准`（金额）只展示；`role=排除` 且原文含"原则上"的（XS-04）标 `需人工`，不得自动判为不通过。可判等的只有学段／学籍／学制／年级／身份类字段。
- **版本锚定**（D-010 的最小实现）：同项目标准类冲突按文件生效/发布日期取最新，旧的标 `superseded=1` 保留原文；同一版本内的多条标准（"平均 3700"与"区间 2500—5000"）互为补充，不互相替代。实测 4 条被替代：财教〔2021〕310号 的助学金 3300，财教〔2024〕181号 的国奖 10000／励志 6000 被 2026 省级办法吸收。
- **收入分档与档位**（字段字典 v2）：政策只给"平均 3700、区间 2500—5000、可分 2—3 档"（GZ-06、GZ-10），**不给收入档界、也不给"哪一档"的映射**。因此 `income_band` 只作参考输入（只存区间不存金额），`school_tier` 由学校定；档位结论只能是"区间参考 + 需核实"，要变成确定值必须补校级分档细则或粤教助〔2023〕2号。
- **覆盖自查**：`coverage` 列出"含资格关键词但无原子"的条款，并区分"本范围外"（职责、预算、学前/中职/高中、程序性）与"真漏抽"。实测 3 份文件真漏抽 0（范围外 28 条）。

## 判等实现（R-003 首版，CLI 级）

`tools/triage.py` + `data/projects.json`（5 个项目的满足路径）+ `data/samples/students.json`（合成样例）。判等完全由代码完成，模型不参与（D-004）。

- **结论判定**：任一满足路径内原子全真 → 可申请；所有路径均为假 → 暂不适用；其余（含未确定、评审类、人工排除）→ 需核实。
- **字段口径**：`未认定` → 暂不适用并在依据里说明"尚未取得认定结论"；`待认定` → 需核实；`需评审` 原子（特别优秀／品学兼优）恒为需核实，学生自评不参与判等；`需人工`（XS-04"原则上不重复享受"）只在学生已获省财政其他专项时把结论降为需核实，不当作排除依据。
- **引用**：每条结论挂 ≥1 条 `clause_id` + 原文 `quote` + `char_start/char_end`，同一 clause 内被包含的短片段自动去重；无条款则不出结论（I-1）。
- **版本**：只加载 `superseded=0` 的 26 条现行原子；输出带 `policy_version` 与 `policy_verified=false`，文号未核前不得对外（I-7）。
- **实测**：`triage --selftest` 12 项断言全过（AC-001 命中 4 项、AC-002 缺项需核实、AC-003 无命中给渠道、I-1、I-2、D-010、评审类恒需核实）。
- **待做**：FastAPI 接口、任务落库、前端单页、材料清单接政策来源。

## 接口与前端实现（T2 首版）

形态：FastAPI（`app/main.py`）＋ SQLite（`data/app.db`）＋ 单页 HTML（`app/static/index.html`，无构建工具）。首版为演示闭环，Vue3／PostgreSQL／Redis 待 P3 压测后按 D-006 归位。

| 接口 | 作用 | 约束 |
|---|---|---|
| `POST /api/triage` | 提交原子字段，返回三档结论 | 参数越界返回 422，不静默修正；不参与判等的字段（`standard_amount`）不接受 |
| `GET /api/triage/{task_id}` | 查历史任务 | 任务不存在返回 404 |
| `GET /api/clause/{id}` | 回点原文 | 返回条款正文、正文偏移、官方页面 URL、台账状态 |
| `GET /api/export/{task_id}` | 导出材料包 | Markdown，含 AI 声明、版本号、文号未核提示 |
| `GET /api/fields` | 字段字典 | 前端据此渲染表单，避免两侧字段表漂移 |
| `GET /api/samples` | 合成样例 | 演示用，不含真实学生信息 |
| `GET /api/health` | 健康检查 | 返回现行原子数、任务数、`policy_verified=false` |

- **落库**：`triage_task(task_id, created_at, policy_version, policy_verified, student_json, result_json, status)`；不存姓名（I-4），存版本号以便回溯（D-005）。
- **前端**：三档用色区分（可申请青、需核实琥珀、暂不适用灰）；条款可点击弹层看原文，弹层固定提示"文号未核"；页面恒显 AI 声明（I-2）；`?case=complete` 一键出结果，供演示与截图。
- **待做**：Docker 一键起、断网演示、复核申诉状态机、真实身份对接、材料清单来源。
