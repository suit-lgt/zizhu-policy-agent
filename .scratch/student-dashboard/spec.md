# 学生工作台参考图布局设计

状态：首页与问答交接已实现，待浏览器视觉与交互验收。参考用户提供的“数智一体化平台”截图，只借鉴信息分区和主次关系，不复刻其政务业务内容或装饰细节。

## 目标

学生登录后能在一屏内看见自己的待办、进入政策咨询或资格初判、回到最近办理记录，并理解政策依据与人工复核边界。首页不新增资格判定，不将命中数量包装成成功率。

## 现状与约束

- `frontend/index.html` 已有会话身份、本人初判记录、任务统计、政策覆盖层级和 `/api/health` 已核文统计。
- 学生政策咨询已经在 `frontend/qa.html` 实现；新首页的咨询组件须复用这一入口，不能复制一份问答状态或私有会话逻辑。
- 资格结论、引用与任务状态沿用既有 API 和页面。没有 API 支持的提醒、办事期限或办理渠道不展示为事实。
- 保留 Cookie 登录；首页仅显示会话昵称，不显示姓名、手机号或家庭情况。
- 沿用已有“小暖”政策向导 SVG，并且只在“你的资助政策向导”挂件展示该 IP；不覆盖该素材。
- 页眉品牌与国家/省级/校级层级标记各用独立的语义图案，禁止重复使用系统 IP。小尺寸图标采用本地原创 SVG，保持矢量清晰与精确构图。
- 已尝试使用内置 `image_gen` 生成图像，服务返回 HTTP 403；本轮没有调用需要 API Key 的 CLI/API。

## 设计方向

- **视觉锚点：**右侧大幅“政策助手”主区；小暖只出现在左上向导挂件。页眉使用书页与引导光点组合的品牌徽记；国家使用政务建筑、省级使用地图与定位点、校级使用校园建筑，四种图案的轮廓与材质语义各不相同。
- **色彩：**沿用蓝白政策工作台底色 `#F4F9FF`、主蓝 `#0B63D6`、深蓝 `#082752`、青色 `#22C7D9`；国家用蓝金、省级用青绿、校级用暖橙。卡片白底，少量细边界，层级靠留白与尺寸区分，不叠加多重渐变和重阴影。
- **排版：**沿用系统字体栈；正文至少 14px，关键标题 24–30px，辅助信息不低于 12px。标题、数值、说明左对齐；欢迎语可在助手主区居中。
- **间距与圆角：**8px 基线；主容器 20px 圆角，普通组件 14px，内部控件 10px。避免所有区块做成同尺寸卡片。
- **交互：**只在用户操作后发生状态变化；焦点态清楚；动效 150–220ms，并遵守 `prefers-reduced-motion`。

│ 品牌/学生工作台       初判   政策问答   办理进度       模式/账号 │
├──────────────────┬───────────────────────────────────────────────┤
│ 欢迎与小暖       │ 新咨询 / 历史入口                              │
│ 本人办理概览     │                                               │
│                  │              嗨，我是小暖                       │
│ 待办事项         │       我可以帮你查政策、理清办理步骤             │
│ · 待核实 任务 A  │                                               │
│ · 复核中 任务 B  │  [问题输入区域；提交后进入现有政策问答工作台]      │
│                  │                                               │
│ 政策覆盖         ├──────────────────────────┬────────────────────┤
│ 国家 省级 校级   │ 常用功能：初判/问答/进度  │ 政策库状态/已核文数 │

主网格采用 300px 左栏与弹性主栏；主栏内助手区占主要高度，底部工作区按 1.4:1 分配。宽度不足 1080px 时改为单栏，待办与覆盖信息排在主助手之后；手机上助手输入区和主操作优先，待办、政策状态折叠在后。

## 功能区与数据来源

| 区域 | 内容与动作 | 数据来源/规则 |
|---|---|---|
| 顶部导航 | 学生工作台、AI 初判、政策问答、办理进度；账号与离线/在线状态 | 沿用现有页面、身份与 Provider 状态 |
| 欢迎/IP 挂件 | 使用会话昵称问候；展示小暖、简短引导和“开始初判”主操作 | `api/auth/me`；现有 `mascot-xiaonuan.svg` |
| 待办挂件 | 展示本人最近 3 条有动作需求的任务；每条可打开该任务办理页；空态引导开始初判 | `api/my-tasks`；仅映射现有状态 `reviewing`、`returned`、`appealed` 等，不推断截止时间 |
| 政策助手 | 文本框、常见政策问题快捷项、“开始咨询”按钮；按钮跳转 `qa.html` 并带入已输入问题，由现有工作台建立会话和回答 | 现有 `qa.html` 与问答会话 API；需增加经过长度限制与 URL 编码的预填参数解析；不得自动提交个人资格判断 |
| 常用功能挂件 | “描述情况”“查政策”“看进度”三个清晰入口 | 复用 `triage.html`、`qa.html`、`progress.html` |
| 政策数据挂件 | 显示已核文/政策总量与“只检索已发布条款”；不使用环形图或增长箭头暗示绩效 | `api/health` 的 `policy_docs_verified`、`policy_docs_total` |
| 固定提醒 | 显示“AI 初判仅供参考，最终以资助部门认定为准” | 项目不变量 I-2；各屏可见 |

“待办”只代表现有任务状态对应的下一步，不创建新的通知、截止日期或自动申请功能。政策助手仅负责把问题交给现有问答；有个人资格判断意图时仍引导进入初判表单。

## 交互与状态

1. 页面先校验 Cookie 会话和学生角色；未登录或角色不符仍跳登录页。
2. 任务、政策统计异步加载时保留固定尺寸骨架；接口失败时显示可理解的重试文案，不以 0 伪装真实计数。
3. 无任务时显示“还没有办理记录”，提供“开始初判”；不显示空白图表。
4. 输入为空或仅空白时禁用咨询提交；最长 1200 字。问题仅通过同标签页 `sessionStorage` 一次性带入，问答页读取后立即删除；不放进 URL，不自动发送，不写入持久化浏览器存储。
5. 以键盘 Tab 可访问所有入口；输入区有真实 label；焦点环不被 sticky 顶栏遮挡；点击目标手机端不少于 44px。

## 验收标准

- AC-01：登录学生可从首页进入初判、政策问答和办理进度；每项入口只触发对应既有流程。
- AC-02：待办只由本人 `/api/my-tasks` 返回的任务生成；每项链接携带正确任务 ID；无数据与请求失败状态可区分。
- AC-03：首页政策助手传入问题后，现有问答页显示预填问题；需要用户确认后才发送，不自动创建回答或初判。
- AC-04：已核文指标来自 `/api/health`；接口失败时显示未知/不可用，不显示伪造数字。
- AC-05：不显示家庭明细、证件号或姓名；完整展示 I-2 固定提醒。
- AC-06：桌面两栏清楚、无横向滚动；768px 与 375px 下单栏排序合理、主操作先于辅助挂件。
- AC-07：键盘焦点清楚、图片有替代文本、状态不只靠颜色表达；减少动态效果偏好生效。
- AC-08：布局复用现有蓝白视觉变量与小暖素材；不增加依赖、不改后端判等或权限。
- AC-09：页眉品牌标记、国家、省级、校级四处使用四种不同图案；图案语义分别为政策服务、国家政务、省域地图、校园建筑；仅“你的资助政策向导”挂件使用小暖 IP。
