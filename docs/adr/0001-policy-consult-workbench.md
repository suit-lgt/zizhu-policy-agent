# ADR-0001：证据驱动的政策咨询与办理工作台

日期：2026-11-08。状态：采纳为本轮设计方向，新增功能尚未实施。

## 背景

现有问答有发布版快照、引用和离线兜底，但浏览器只留最近问题，单轮取证难以承接连续办理需求；当前原文弹窗又不锚定旧轮版本。需要引入同源证据、持久化轮次和业务行动，同时保持资格规则不交给模型。

## 选择

1. 保留 FastAPI＋SQLite＋多页 HTML，新增最小会话／轮次服务；不为界面形态迁移而引入另一套数据库、前端框架或编排框架。
2. 使用 EvidenceBundle 统一回答、面板、引用和导出；面板纯函数生成。
3. 按轮次冻结政策版、查询范围、证据与材料配置；解释已有任务时优先任务基线。
4. 保留完整模型回答校验，正文通过后再分块展示。先发送确定性依据，不传未经校验的政策结论 token。
5. 新会话只接受真实 Cookie 登录；普通对话最小保存，业务审计独立不可被会话删除。
6. 个人资格只通过既有规则初判或本人任务解释；新增咨询不替换六代理。
7. 旧 /api/qa 兼容；新端点逐步调用共用证据层，不平行维护两套政策检索语义。

## 备选与代价

只扩充提示词：不能解决历史、权限、快照和办理联动，因此不足。
直接复制教研咨询模块：带入不适用问域、框架和口径，且原 token 流未满足本项目展示前校验要求。
原生 token 流：首字响应快，但未经完整校验的内容可能先展示；首版选完整校验＋分块展示，接受正文稍晚出现。
新增外部队列与数据库：不是当前设计必要条件；规模或恢复要求超过单进程 SQLite 能力时再用实测决定。

## 验证与重议

按新 spec 的 PC-AC01—22 验收。真实并发、服务恢复、在线时延和事实支持未实测，不报告已达标。数据量、部署进程数或延迟要求发生实质变化时再重议存储／队列，不凭框架偏好迁移。
