# 部署与端口设计

本文件给出上线部署时的端口切分、入口约束、启动顺序与验证方法。默认端口按"公共／教师／管理／接口"四端划分，一个镜像、一个容器、单进程；容器内仍是 8000，宿主侧按端映射到不同端口。

## 1. 端口规划

| 宿主端口 | 端 | 主要入口 | 允许访问 | 明确不提供 |
|---|---|---|---|---|
| 8000 | 学生／公共端 | `/`、`/login.html` | 学生初判、问答、材料、渠道、申诉、隐私授权、登录注册 | `/admin.html`、`/review.html`（307 跳对应端） |
| 8001 | 教师／审核端 | `/review.html`、`/login.html` | 待办、复核录入、批量初筛、两级看板、预警、报送 | `/admin.html`（307 跳 8002） |
| 8002 | 管理端 | `/admin.html`、`/login.html` | 账号审核与权限、政策入库／核文／切块／发布／回滚、字典、校级分档、审计、导出审批、报表 | `/review.html`（307 跳 8001） |
| 8003 | 接口／健康检查 | `/api/*`、`/docs`、`/openapi.json` | 监控、联调、健康检查 | 全部网页入口（返回 404） |

容器内部只监听 `0.0.0.0:8000`；`docker-compose.yml` 将宿主 8000–8003 都映射到容器 8000。应用通过请求的 `Host` 头识别宿主端口并做入口约束，因此浏览器必须使用带端口的地址访问，例如 `http://服务器IP:8001/review.html`。

数据层使用 SQLite 文件（`data/app.db`、`data/staging/policies.db`）挂在数据卷上，不开数据库网络端口；不要用多副本共享同一 SQLite 文件。若后续迁移 PostgreSQL，再单独规划 5432 并只允许应用容器内网访问。

三张业务页（学生端、审核台、管理后台）不再用请求头模拟身份：未登录或角色不匹配会跳到 `/login.html`；管理后台必须以管理员账号登录后才能调用管理接口。

登录成功后按角色跳转到对应端：学生 → 8000，教师／辅导员 → 8001，管理员／审计员 → 8002；如果当前已在某个端端口，会跳到该角色对应的端，避免在错误端继续操作。

页面内原有的相对导航由服务端兜底：在管理端点“任务复核台”会自动 307 跳到 8001，审核台点“管理后台”会跳回 8002；用户不需要手工改地址。管理端顶部另有“注册审核”直达入口（`/admin.html?tab=registrations`），新账号申请在管理端处理，不在教师审核台。

## 2. 端口与权限的边界

- 端口切分解决"入口不混用"和"对外只暴露必要端"；真正的数据权限仍由会话、角色和后端接口校验控制，不能只靠端口。
- 页面在错误端会 307 跳到对应端，不会把用户留在 404：8000 的 `/admin.html` → 8002、`/review.html` → 8001；8001 的 `/admin.html` → 8002；8002 的 `/review.html` → 8001。这样页面导航里的相对链接也能跨端落到正确入口。
- 接口在错误端直接返回 404：8000 不提供管理接口（账号、审计、上报、校级分档、政策核文／切块／发布／回滚、导出审批）；8001 不提供管理接口；8002 不提供审核台与初判接口（`/api/triage`、`/api/review/*`、`/api/board`、`/api/tasks`、`/api/warnings`、`/api/appeals` 等）；8003 只提供 `/api/*`、`/docs`、`/openapi.json`。
- 8003 只适合内网监控或网关转发，不应直接暴露到公网。
- 生产部署建议在 Nginx／网关层再加一层：8002 仅放行运维与资助中心固定 IP，8001 仅放行校园内网，公网只开 8000；同时启用 HTTPS，禁止明文口令传输。
- 若通过反向代理访问，必须保留原始 `Host` 头（如 `proxy_set_header Host $host:$server_port;`），否则应用无法识别端端口，入口约束不会生效。反向代理也可以改为按域名分流，此时应在网关层完成同样的路径限制。

## 3. 管理员初始账号

部署首次启动会自动创建默认管理员，已存在则不会覆盖已修改过的密码：

| 昵称（登录名） | 初始密码 | 角色 | 状态 |
|---|---|---|---|
| `admin` | `admin@2026` | 管理员 | 启用 |

首次登录后请在管理端"账号权限"里重置为自己的强密码；默认密码只用于首次部署验收，不应长期沿用。初始化逻辑在 `backend/app/accounts.py::ensure_bootstrap_admin`，由 `backend/app/main.py` 在 `db.seed()` 之后调用，幂等。

## 4. 启动与验证

```powershell
cd D:\ai_code\2026年挑战杯\资助政策智能体
docker compose config          # 静态校验，应看到 4 条端口映射
docker compose build
docker compose up -d
docker compose ps              # 期望 Up (healthy)
```

逐端验证：

```powershell
# 学生端
Invoke-WebRequest http://127.0.0.1:8000/api/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8000/login.html -UseBasicParsing
# 教师端：审核页 200，管理页 307 跳管理端
Invoke-WebRequest http://127.0.0.1:8001/review.html -UseBasicParsing
# 管理端：管理页 200，审核页 307 跳教师端
Invoke-WebRequest http://127.0.0.1:8002/admin.html -UseBasicParsing
# 接口端：健康检查 200，网页 404
Invoke-WebRequest http://127.0.0.1:8003/api/health -UseBasicParsing
```

管理员登录接口验证：

```powershell
$body = @{ nickname = "admin"; password = "admin@2026" } | ConvertTo-Json
Invoke-WebRequest http://127.0.0.1:8002/api/auth/login -Method POST -ContentType "application/json" -Body $body -SessionVariable s -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:8002/api/auth/me -WebSession $s -UseBasicParsing
```

预期 `role=admin`、`user=admin`。

## 5. 上线前检查

- 修改默认管理员密码；确认 `admin` 账号只用于管理，不用于日常问答。
- 在 `.env` 中设置 `LOG_LEVEL=WARNING`，避免生产日志过多；日志已做手机号等脱敏。
- 开发机可四端直连（8000—8003）；正式公网不直接暴露四端口，统一走 Caddy 子路径，详见 `docs/公网部署记录.md`。
- 数据卷 `./data` 挂载到容器 `/app/data`，定期备份 `data/app.db` 与 `data/staging/policies.db`。
- SQLite 为单写库，保持单容器单进程；若要横向扩容，先迁移到 PostgreSQL，不能直接多副本共享同一 SQLite 文件。
- 上线前复跑：`tests/smoke.py`、`tests/auth_flow.py`、`tests/ui_flow.py`、`tests/version_flow.py`、`backend/tools/qa_eval.py`、`backend/tools/fact_support.py`。
