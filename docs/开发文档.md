## 1. 系统定位与边界

**做**：把"我的家庭与学籍情况"翻译成"能申请什么、要什么材料、去哪办、依据哪条"，每条结论可回点政策原文，人工复核兜底。
**不做**：资格认定、资金发放、替代政务系统、跨省政策全覆盖、模型自动判定结论、保存原始录音与家庭明细。

硬约束（不可协商，来自 AGENTS.md 的 I-1—I-7）：
- I-1 无条款不出结论；无命中只给渠道。
- I-2 只出"可申请／需核实／暂不适用"，永不输出"符合／不符合"，页面恒显免责。
- I-3 引用由系统拼装，可回点原文偏移。
- I-4 只采判定必需字段，库内不存姓名与家庭明细。
- I-5 复核与申诉留痕不可删（审计表追加写，数据库层禁改禁删）。
- I-6 系统与文档不出现"挑战杯""获奖"。
- I-7 文号、机关、生效日期未核的政策不得进入对外结论（`policy_verified=false` 必须显性输出）。

## 2. 角色与权限

演示态用请求头 `X-Role` 标识角色（`student`／`counselor`／`admin`／`auditor`），首版不接统一身份认证，交付前替换为学校 CAS/OAuth，权限判断代码位置不变（`app/auth.py` 的 `current_user`）。

| 能力 | 学生 | 辅导员 | 资助中心管理员 | 审计员 |
|---|---|---|---|---|
| 提交初判 | ✓ | — | ✓ | — |
| 查看本人任务 | ✓ | — | ✓ | — |
| 提交复核申请 | ✓ | — | — | — |
| 发起申诉 | ✓ | — | — | — |
| 查看本院任务列表 | — | ✓ | ✓ | — |
| 复核（通过／退回） | — | ✓ | ✓ | — |
| 申诉裁决、改判 | — | — | ✓ | — |
| 政策核文、发布、回滚 | — | — | ✓ | — |
| 查看审计日志 | — | — | ✓ | ✓ |
| 维护校级分档 | — | — | ✓ | — |
| 导出材料包 | ✓（本人） | ✓（本院） | ✓ | — |

实现：`require_role(...)` 依赖注入；越权返回 403 并写 `audit_log`（action=`denied`）。学生只能访问 `student_json` 中 `owner` 与登录用户一致的本人任务（演示态以 `X-User` 标识，缺省 `student_demo`）。

## 4. 数据模型与状态机

### 4.1 表

政策侧（`data/staging/policies.db`，只读事实来源）：`policy_staging`、`policy_clause`、`policy_atom`、`crawl_run`。

业务侧（`data/app.db`）：

| 表 | 关键字段 | 说明 |
|---|---|---|
| `app_user` | user_id、name、role、enabled、updated_at | 演示账号种子；`enabled=0` 时接口一律 403 |
| `triage_task` | task_id、created_at、owner、policy_version、policy_verified、student_json、result_json、status、consent | 不存姓名 |
| `review_event` | id、task_id、project_id、action、actor、role、reason、created_at | 复核／改判流水 |
| `appeal` | id、task_id、project_id、reason、status、created_at、handler、handled_at、decision | 申诉 |
| `audit_log` | id、actor、role、action、target、detail、created_at | 追加写，触发器禁改禁删 |
| `policy_verify` | doc_id、doc_no、issuer、effective_from、verifier、verified_at、note | 核文结论 |
| `policy_version` | version_id、created_at、published_by、label、docs、clauses、atoms、status、snapshot_json | 发布快照 |
| `material_item` | id、project_id、name、source_type、source_clause_id、required、note | 材料与来源 |
| `school_tier` | id、level、income_band、amount、note | 校级分档（空＝待细则） |
| `export_request` | id、task_id、requester、role、note、status、created_at、reviewer、reviewed_at、review_note | 导出审批流；默认 `pending` |

### 4.2 状态机

任务：`triaged`（已出结论）→ `reviewing`（提交复核）→ `approved`／`returned`；`returned`／`approved` → `appealed`（申诉）→ `amended`（改判）或维持原结论。
政策文件：`pending_verify` → `verified` → `published` → `superseded`／`archived`。
政策版本：`draft` → `current` → `rolled_back`（历史保留，当前指针切换）。

### 4.3 判等口径（D-011）

任一满足路径全真＝可申请；全路径皆假＝暂不适用；其余（未填、待认定、评审类、人工确认项）＝需核实。`未认定` 判暂不适用并说明；评审类恒需核实；`standard_amount` 只展示不判等。

## 10.2 v0.5 增量（2026-11-07）：真实账号闭环、多智能体协同、本地上传入库

### 10.2.1 账号闭环（`backend/app/accounts.py`）

| 能力 | 接口 | 规则 |
|---|---|---|
| 注册 | `POST /api/auth/register`（公开） | 昵称＋密码必填，学校／手机号选填；昵称即登录名，`^[\u4e00-\u9fa5A-Za-z0-9_-]{2,20}$`；密码 ≥8 位且同时含字母和数字；手机号只落库脱敏形式（`138****5678`），完整号码不存；提交后 `pending`，`enabled=0` |
| 审核 | `GET /api/admin/registrations`、`POST /api/admin/registrations/{id}/review`（admin） | 通过写角色（默认 student，可指定 counselor/auditor/admin）并置 `active`／`enabled=1`；驳回必填理由（422），重复审核 400 |
| 登录 | `POST /api/auth/login` | 待审核 403、已驳回 403 附理由、停用 403；成功签发 `secrets.token_urlsafe(32)`，写 `user_session`，HttpOnly Cookie `fund_session`（`samesite=lax`），有效期 12 小时 |
| 身份 | `GET /api/auth/me`、`/api/auth/whoami` | 会话优先、请求头兜底；`source` 区分 `session`／`header`；演示账号（student_demo 等）无密码，只能请求头演示 |
| 重置 | `POST /api/admin/users/{id}/reset-password`（admin） | 生成一次性临时密码 `Fund@`＋6 位数字，只在响应返回一次；置 `must_change_password=1`；旧会话全部失效 |
| 改密 | `POST /api/auth/change-password`（需会话） | 校验原密码与新密码强度；成功后清空该用户全部会话，要求重新登录；演示态（header）调用返回 400 |

口令用标准库 PBKDF2-HMAC-SHA256（20 万轮、16 字节随机盐），校验用 `hmac.compare_digest`，不引第三方库。

文字指引常量随接口返回：`GUIDE_REGISTER`（注册四步）、`GUIDE_PENDING`、`GUIDE_LOGIN`、`GUIDE_ADMIN_REVIEW`（审核四步）、`GUIDE_RESET`、`GUIDE_UPLOAD`（上传四步）。登录页与学生端／审核台／后台的“登录/注册”入口直接渲染这些步骤。

### 10.2.2 多智能体协同（`app/agents.py`）

`POST /api/triage` 改走 6 个职责单一的确定性代理（不调模型）：

1. `intake 受理`：校验字段、统计空值；
2. `rule 判等`：复用 `backend/tools/triage.py` 出三档结论；
3. `cite 依据核验`：逐条回 `policy_clause` 比对 `clause_id` 与引文偏移（支持条款内相对偏移与全文绝对偏移），核不到即标 fail；

### 10.2.3 本地上传入库与发布门禁（`app/ingest.py`）

- `POST /api/policy/upload`：`{filename, content_b64}`，≤10MB；`.docx` 优先 python-docx，缺失时解 `word/document.xml` 兜底；`.pdf` 用 pypdf（镜像已装 5.9），缺解析器返回 501 不静默失败；`.txt/.md/.csv` 依次试 utf-8／utf-8-sig／gb18030。正文 <50 字 422；同文件 SHA-256 去重返回 409；原文件存 `data/uploads/<hash12>_<filename>`，`policy_staging` 落 `host='upload'`、`status='pending_verify'` 草稿。
- `POST /api/policy/{doc_id}/split`：要求已核文（否则 400），按“第X条”重建条款；切完把该 doc 条款置 `verified/publishable=1`；0 条返回 422。
- `verify_doc` 同时把该 doc 已有条款置可发布；`publish` 增加“未切块不得发布”（400）。
