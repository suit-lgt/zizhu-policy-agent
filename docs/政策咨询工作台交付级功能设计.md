# 政策咨询工作台交付级功能设计

状态：设计稿，待评审。日期：2026-11-21。  
范围：以“学生政策咨询会话”为核心，覆盖它与政策原文、本人初判、办理进度的联动；审核端、管理端、政策发布端只写与咨询相关的接口边界，不展开成另一套完整需求。  
边界：本文不生成代码，不把设计建议写成已实现事实。所有“当前状态”来自 2026-11-21 的只读代码走查和既有验证记录；“目标状态”才是后续开发要交付的内容。

## 0. 交付结论摘要

当前系统已经具备一条完整的技术闭环：真实 Cookie 登录 → 创建会话 → 提交问题 → 固定政策版本 → 生成证据包和面板 → FactPack 交给模型或模板组织语言 → 事实校验 → 落库 → SSE 回传 → 历史回看、导出、原文回看、初判引导。

但按“可直接交付给学生使用”的标准，当前仍有四个必须处理的交付阻塞点：

1. **证据总是降级**：快照元数据把适用范围和有效期确认位固定写为 false，导致每条命中证据都只能标为 `needs_verification`，系统无法输出“已核实适用”的正面状态。根因既有代码问题，也有政策核文数据缺口。
2. **事实锚点校验未闭合**：提示词要求模型逐句写 `[fact_id]`，但校验函数只检查 claims 是否是已知 id，没有校验正文里的锚点。逐句可回溯承诺目前只靠提示词约束。
3. **长任务租约可能误杀**：轮次租约在创建时一次性设为 120 秒，执行期间不续约；并发排队或在线模型慢响应时，可能被恢复逻辑误标为 `interrupted`，导致已生成回答无法写入。
4. **交付态 UI 和可访问性不足**：加载态、错误播报、终止态提示、断点体系、低对比度小字、键盘与读屏语义未达到“面向真实学生交付”的清晰程度。

建议交付顺序：先修 P0 机制风险和数据缺口，再补 UI/可访问性，最后完成真实端点评测、人工语义签认和学生实操。在线能力未通过 50 题回归前，只能描述为“链路已实现、单条已实测”，不能写成“在线答案已达标”。

## 2. 用户、核心场景与成功标准

### 2.1 主要用户

| 用户 | 当前任务 | 交付时要保证 |
|---|---|---|
| 学生本人 | 问政策条件、金额、材料、流程，理解本人已有初判结果 | 不问也知道下一步；每句话有出处；不误以为聊天已经完成资格认定 |
| 学生本人（个人资格追问） | “我能不能申请？” | 不在自由聊天中判等，引导到初判表单或已有任务 |
| 政策/资助管理人员 | 政策口径可追溯，结果可解释 | 版本、文号、原文、偏移、模型模式、降级原因都可查 |
| 系统审计方 | 会话不可越权，敏感信息不落库 | 仅本人可读；审计只写元数据；普通删除不影响业务留痕 |

### 2.2 核心场景清单

| 场景 | 用户目标 | 交付价值 | 当前状态 |
|---|---|---|---|
| S1 首次政策咨询 | 问一个政策问题，得到有出处的解释 | 建立信任，避免“只给结论不给依据” | 已实现主体链路 |
| S2 多轮追问 | 连续问条件、材料、流程，继承项目与版本 | 减少重复描述 | 已实现，需补状态提示 |
| S3 个人资格追问 | 问“我能申请吗” | 正确引导初判，不在聊天里判等 | 已实现边界，需补 UI 说明 |
| S4 本人任务解释 | 查看历史初判结论、缺项、复核状态 | 把政策解释和个人任务连起来 | 部分实现，进度 handoff 未闭合 |
| S5 原文回看、导出、删除 | 回看当轮原文，导出记录，删除普通历史 | 可追溯、可携带、可控隐私 | 已实现主体，需补 retention 口径 |
| S6 咨询中实时计算 | 在问答中基于结构化确认字段重新计算 | 满足“回答时可以计算”的增强目标 | 设计约束已写，代码未实现 |

## 5. 核心场景交互设计

### 5.1 S1：首次政策咨询

前置：学生已通过 `fund_session` 登录，当前存在已发布政策版本。

| 步骤 | 用户动作 | 页面反馈 | 后端处理 | 数据/状态 |
|---|---|---|---|---|
| 1 | 进入 `/qa.html` | 显示本人咨询记录、欢迎卡、4 个预置问题；未登录跳登录 | 校验 Cookie；拉取 options 与 sessions | 无新数据 |
| 2 | 点击预置问题或输入问题 | 问题进入输入框；发送按钮可用；字数 2–1200 校验 | 无 | 无 |
| 3 | 点击发送或按 Enter | 按钮禁用，显示“检索依据中/核验回答中”，显示停止按钮 | 若当前无会话先创建；生成 client_request_id；提交 turn | `qa_session` 新建；`qa_turn=accepted` |
| 4 | 等待首包 | 对话区显示占位，依据区显示骨架；状态区播报“正在检索同版政策” | 取 turn → 生成 QueryContext → 固定版本 → 检索证据 → 生成 panel | `state=preparing`，随后 `evidence_json/panel_json` 写入，`state=validating` |
| 5 | 收到 meta | 先显示政策版本、范围、证据数量和确定性面板 | SSE 发送 meta，只含已核验结构化数据 | 轮次证据已冻结 |
| 6 | 收到 chunk | 正文逐段出现；状态显示“答案校验通过，正在展示” | 仅发送已校验正文切片 | 无新写入 |
| 7 | 收到 citations/done | 显示引用列表与终态；可选“查看本轮依据/导出/进入初判” | 保存 answer、citations、mode、fallback、completed_at | `state=completed/clarified/refused` |
| 8 | 断流或超时 | 页面提示“连接中断，正在查询已保存状态”，按 turn_id 恢复 | 不重新提问；查询或重订阅事件 | 终态以库为准 |

失败分支：

- 401/403：停止 SSE并跳登录。
- 409：上一轮仍 ACTIVE，提示等待或取消，不创建新轮。
- 422：问题长度、request id 或 confirmed context 非法，输入区附近显示具体原因。
- failed/interrupted：显示“本轮未生成完整说明”，提供“重新尝试”，重试使用新的 request id并关联上一轮。

### 5.2 S2：多轮追问与项目切换

| 步骤 | 用户动作 | 页面反馈 | 后端处理 | 约束 |
|---|---|---|---|---|
| 1 | 在 S1 后问“要什么材料” | 继承上一轮项目与版本；意图切到 materials | 读取 tail context；parent_turn_id 必须等于尾轮 | 防串轮 |
| 2 | 点击依据面板中的项目按钮 | 输入“请继续说明申请条件”，confirmed_context 带 project_code | parse 只允许合法项目代码 | 只切项目，不改政策版本 |
| 3 | 发布新版后，页面提示“当前查看历史版本” | 显示“下一问使用最新政策”按钮 | 当前轮仍按旧版；用户显式确认后下一轮才切当前版 | 旧轮不变 |
| 4 | 问“还有呢/继续” | 继承上一轮 intent，避免误判为泛泛政策条件 | parse 使用 previous intent | 仅限白名单短语 |
| 5 | 问域外内容 | refused，显示“当前发布版本没有找到足以回答此问题的政策依据” | branch=refused，不进入模型正文 | 不硬答 |

### 5.3 S3：个人资格追问

| 步骤 | 用户动作 | 页面反馈 | 后端处理 | 硬边界 |
|---|---|---|---|---|
| 1 | 输入“我家庭收入……我能申请吗” | 输入框保留用户原文供编辑，但发送后库里只存脱敏语义 | parse 识别 personal_guidance | 不写个人原文 |

| 3 | 依据区显示 | “个人情况请在初判表单确认”，显示“核对情况，进入初判” | 生成 handoff，只含 project_codes、version、source_turn_id | 不携带收入/身份 |
| 4 | 点击初判 | 跳转 `triage.html?handoff=...`，页面提示“已带入项目线索，请核对本人情况并授权” | 初判创建时消费 handoff | 未确认、未 consent 不创建任务 |

交付要求：学生必须能从页面文字看出“聊天没有替我判定资格”。

### 5.4 S4：本人任务解释与进度联动

### 5.6 S6：咨询中实时计算（目标增强，当前未实现）

这是用户明确提出的能力目标，但当前只在设计文档中落边界。若后续实现，必须按以下流程，不得从自由聊天直接抽取个人事实计算。

| 步骤 | 设计约束 |
|---|---|
| 1 | 学生点击“按结构化信息计算”，页面展示字段卡；字段来源只能是 `data/fields.json` v2 白名单 |

| 7 | 没有条款、版本不可引用、范围/有效期未核实时返回 need_check/refused，不让模型补足事实 |

## 7. 状态与数据流转

### 7.1 轮次状态机

| 状态 | 含义 | 写入时机 | 页面表现 | 下一状态 |
|---|---|---|---|---|
| accepted | 请求已接收并去重 | turn 创建成功 | “已接收/准备中” | preparing 或终态 |
| preparing | 正在构建 QueryContext 与证据 | worker 开始处理 | “检索依据中” | validating/failed |
| validating | 证据和面板已冻结，正在生成/校验正文 | prepare 完成 | “核验回答中” | completed/clarified/refused/failed |
| completed | 已生成并通过校验的说明 | finish 成功 | 正文、引用、终态 | 终态 |
| clarified | 需要学生选择项目或任务 | 无项目、无 task_id | 澄清按钮/空态 | 新轮 |
| refused | 无依据、域外或范围不支持 | branch=refused 或无 items | 明确“未找到依据” | 新轮 |
| failed | 容量不足、执行异常、校验后无可用模板 | 异常或容量满 | “生成失败，可重试” | 新轮 |
| cancelled | 用户主动停止 | cancel 接口 | “已停止” | 新轮 |
| interrupted | 租约过期/服务重启恢复 | recover | “处理已中断，可重试” | 新轮 |

### 7.2 数据流

| 阶段 | 输入 | 处理 | 输出/落库 |
|---|---|---|---|
| 请求入口 | question、client_request_id、parent_turn_id、可选 task_id/confirmed_context | 登录校验、长度/格式校验、同会话 ACTIVE 检查 | `qa_turn` accepted |
| 语义解析 | 原始问题、上一轮 context | 白名单意图/项目/topic 解析，个人线索改写 | `context_json` 写入；原文不存 |
| 版本固定 | context、payload.use_current_version、previous/task | 一般咨询固定当前版；任务解释固定任务版 | context.policy_version 冻结 |
| 证据构建 | question=sanitized_question、context、task | 发布快照检索、resolve、材料分级、警告生成 | evidence_json 写入 |
| 面板构建 | EvidenceBundle | 纯函数按 intent 选块 | panel_json 写入 |
| FactPack | EvidenceBundle | 生成 quote/conclusion/material/procedure facts | 模型输入，不落单独表 |
| 语言组织 | FactPack、prompt | offline 模板或 online 模型 JSON | 候选 answer + claims |
| 校验 | 候选正文、facts | 结构、claims、锚点、数字、文号、结论、措辞、敏感 | 通过则采用；失败回退模板并记录 fallback |
| 终态保存 | answer、citations、state、mode | finish 更新轮次；写审计 | completed/clarified/refused/failed |
| 传输 | 已保存 turn | SSE meta→chunk→citations→done | 前端渲染；断流可恢复 |
| 联动 | turn_id/evidence_id/task_id | 原文回看、导出、handoff | Markdown 或跳转；业务任务不被误改 |

### 7.3 数据表职责

| 表 | 当前字段要点 | 交付约束 |
|---|---|---|
| qa_session | id、owner、topic、created_at、updated_at | 只存通用主题；本人可见；可删除 |
| qa_turn | request id 唯一、sanitized_question、context/evidence/panel/answer/citations/task JSON、state、mode、fallback、lease | 不存个人原文；终态必须落库；租约需可恢复 |
| qa_handoff | owner、source_turn_id、context、expires、consumed_task_id | 短时、本人校验、一次消费或明确幂等 |
| audit_log | actor、role、action、target、detail | append-only；脱敏；只记元数据 |
| policy_snapshot_* | version_id、clause_id、原子、偏移 | 历史引用不得用当前草稿替代 |
| material_item | 当前为可变配置 | 当轮靠 evidence_json 冻结；长期需版本化 |

| 480–767px | 单列：对话优先，依据在下方/抽屉 | 输入区 sticky；移动端不横向滚动 |
| <480px | 单列紧凑 | 预置问题单列或两列；按钮触摸区 ≥44px；长文号可换行 |

当前冲突：style.css 使用 1180/900/620；qa-workbench.css 使用 1200/1020/680；polish 使用 1020/760/390；JS 用 760。交付前必须收敛为一套断点名称与阈值，并让脚本与 CSS 对齐。

### 11.2 可访问性目标

| 要求 | 交付标准 | 当前问题 |
|---|---|---|
| 语义结构 | 页面有 main、header、aside；区域有 aria-label | 基本已有 |
| 当前位置 | 导航当前项加 aria-current=page | 当前仅 class=on |
| 键盘操作 | 所有按钮/链接可 Tab 到达，Enter/Space 可触发 | 原生控件基本满足 |
| 焦点可见 | 所有可交互元素有可见焦点环 | consult-page 已有，需覆盖所有状态 |
| 读屏播报 | 状态变化用独立 live 区；错误用 role=alert | 当前整段对话 aria-live，错误为 status |
| 忙碌状态 | 对话区 aria-busy=true/false | 缺失 |
| 弹窗 | dialog role/aria-modal/焦点陷阱/Esc | QA 原生 dialog 合规；triage 自定义弹窗不合规 |
| 对比度 | 正文与小字 ≥4.5:1；大字与控件 ≥3:1 | muted-2、placeholder、导航未选中项不足 |
| 减少动效 | prefers-reduced-motion 生效 | 已有基础 |
| 表单标签 | 所有输入有 label 或 aria-label | QA textarea 已有 sr-only label |
| 触摸目标 | 移动端主要按钮 ≥44×44 | 需实测 |

### 12.3 Definition of Done

一个功能只有同时满足以下条件才算交付完成：

1. 用户故事、页面流程、状态、数据字段、权限、错误口径都有文档。
2. 前端可操作，后端有接口，数据库有落点，测试有断言。
3. 自动测试通过，且未执行的项明确标 NOT_RUN。
4. 错误、空态、加载态、终止态都能被用户理解。
5. 权限和隐私通过越权/脱敏用例。
6. 版本、证据、引用、模式、fallback 可追溯。
7. 移动窄屏和键盘流程可完成核心任务。
8. 在线模型能力有独立评测，不与规则链路混算。

## 13. 交付实施顺序

### 第一批：P0 机制闭合

1. 补 `preparing` 状态落库。
2. 补正文 `[fact_id]` 锚点校验，并与 claims 一致性校验。
3. 补 worker 租约刷新和取消协作标志。
4. 补 handoff 一次消费；补进度 task_id 受控引导。
5. 统一任务状态字典。
6. 明确 Policy 元数据核文流程；核文未完成前保持待核实文案。

### 第二批：P0 交付态体验

1. 统一响应式断点，修 680/760 冲突与死规则。
2. 增 loading 骨架、aria-busy、错误 role=alert、终态说明条。
3. 修低对比度小字、placeholder、导航未选中项。
4. 统一弹窗实现，补 triage 弹窗焦点与 Esc。
5. 真机/浏览器窄屏走查。

### 第三批：评测与验收

1. 统一测试计数口径，固定 CI 输出为唯一事实源。

## 15. 一句话交付判据

能交付的版本不是“页面能问、模型能答”，而是：**学生每一次提问都能看到同版依据，系统每次计算都由代码完成，模型每次表达都被事实约束，所有状态、权限、异常和隐私边界都能被测试或人工验收逐条证明。**
