# 政策咨询工作台交付实施规划

状态：执行版。日期：2026-11-21。  
依据：`docs/政策咨询工作台交付级功能设计.md`（设计稿）、`AGENTS.md` 不变量、2026-11-21 只读代码走查。  
说明：本文只记录可核对的现状、决定与验收口径。未执行的外部评测一律写 NOT_RUN，不写成已达标。

---

## 1. 评估结论

现有主链路是真实的：Cookie 登录 → 会话/轮次落库 → 版本固定 → 证据与面板 → FactPack → 事实校验 → SSE → 历史/导出/handoff。设计文档描述的四个交付阻塞点中，三个有明确代码根因，一个是外部流程缺口。

| 设计要求 | 代码现状 | 判定 | 证据 |
|---|---|---|---|
| preparing 状态可见 | `prepare()` 直接写 validating，preparing 从未落库 | 缺失 | `qa_sessions.py:128-130`、`qa_routes.py:21-33` |
| 正文 `[fact_id]` 锚点可机器校验 | 只校验 claims 是已知 id，正文锚点不校验 | 缺失 | `provider.py:196-220`、`prompts/qa_workbench_v2.md:20,27` |
| 长任务不误杀 | 租约创建时 120 秒固定；读接口也调用 recover；无续租 | 缺陷 | `qa_sessions.py:48-52,61,66,74,119`、`qa_routes.py:12-13` |
| 取消协作化 | 只把轮次改成 cancelled，worker 继续跑、槽位继续占用 | 缺陷 | `qa_routes.py:33,69-72` |
| handoff 一次消费 | `consumed_task_id` 有字段但无写入；GET 可重复读 | 缺失 | `qa_sessions.py:25-27,163-181`、`main.py:311-327` |
| 进度联动受控 | 前端直接拼 `progress.html?task=...`，没有短时 handoff | 缺失 | `qa-workbench.js:58`、`progress.html:291-295` |
| 元数据核文后恢复 supported | 快照元数据表在真实库不存在；`snapshot_metadata` 把确认位固定写 false | 缺陷+数据缺口 | `qa_evidence.py:9-27,41-48`；真实库 `policy_snapshot_meta` 不存在；`policy_verify` 有 3 条已核文记录 |
| 状态字典一致 | 咨询页把任务状态写成 reviewed/closed，其余页面用 approved/returned/amended | 冲突 | `qa-workbench.js:8`、`index.html:101-104`、`progress.html:127-130` |
| 加载/错误/终止态 | 没有独立状态区，正文整段 aria-live，错误只有 toast | 缺失 | `qa.html:47,66`、`qa-workbench.js:20-21,70-79` |
| 旧兼容入口措辞 | 裸禁用词「符合/不符合」会误伤原文描述性表述 | 冲突 | `provider.py:26,81-91` |
| 在线 50 题回归 | 未配置在线模型，无法运行 | NOT_RUN | `provider.status()`：offline/configured=false |

## 2. 本轮完善范围

### 2.1 纳入

1. **P0 机制闭合**：preparing 落库、租约续期、读路径不再触发恢复、协作取消、anchors 校验、handoff 一次消费、进度受控 handoff。
2. **P0 元数据机制**：从已有核文记录回填快照元数据；提供管理员显式确认范围/有效期的受控接口；未确认前维持 `needs_verification`。
3. **P0 交付态 UI**：独立状态区、aria-busy、role=alert、终态说明条、统一任务状态字典、导航 aria-current、低对比度小字与占位符修正。
4. **回归测试**：扩展单元测试、接口流测试，新增本轮专项用例。

### 2.2 不纳入及原因

| 项 | 原因 |
|---|---|
| S6 咨询中结构化计算卡 | 设计文档列为第四批，需单独评审；本轮不新增字段卡、授权流与 FactPack 扩展 |
| 在线模型接入与 50 题回归 | 无在线配置与外部凭据；保持 offline，标 NOT_RUN |
| 人工语义签认、学生实操 | 需资助中心与真实学生，外部流程，标 NOT_RUN |
| 导出 PDF、会话保留期自动清理 | P2；保留期需产品决策，首版只保留本人删除 |
| 断点体系大重构 | 只修咨询页冲突的 760/680 与可访问性，不重写全站布局 |

## 3. 功能调整与模块职责

| 模块 | 本轮职责变化 |
|---|---|
| `qa_sessions.py` | 新增 `claim/renew/is_active` 状态与租约操作；移除读接口里的 `recover()`；handoff 增加 kind/task_id 与原子消费 |
| `qa_routes.py` | worker 按状态领取并续租；取消只置标志；新增进度 handoff 与管理员元数据确认接口 |
| `qa_evidence.py` | 快照元数据从 `policy_verify` 回填；新增受控确认函数；不自动宣称范围已核实 |
| `provider.py` | 事实守恒增加正文锚点校验；旧兼容入口收窄判定措辞规则 |
| `main.py` | 启动时只做一次恢复与元数据回填；创建初判任务时消费 handoff |
| `qa.html`/`qa-workbench.js` | 独立状态区、忙碌与终态语义、进度 handoff、状态字典统一 |
| `triage.html`/`progress.html` | 接收并消费 handoff，明确“仅带项目线索/任务定位，不预填个人事实” |

## 4. 接口与数据变化

| 变化 | 契约 |
|---|---|
| `POST /api/qa/turns/{tid}/progress-handoff` | body `{"task_id":"..."}`；校验本人任务；返回 `{id,expires_at,task_id}`，不含个人事实 |
| `PUT /api/qa/policy-meta/{version}/{doc_id}` | 仅管理员；body `{scope_confirmed,validity_confirmed,issuer,effective_from,effective_to,verifier}`；写快照元数据与审计 |
| `GET /api/qa/handoffs/{id}` | 返回值新增 `kind`、`task_id`、`consumed_task_id`；旧字段保持不变 |
| `POST /api/triage` | body 可选 `handoff`；创建任务时原子消费；重复或过期返回 409 |
| `qa_handoff` 表 | 不新增列；kind/task_id 写入 `context_json`，兼容旧行 |
| `policy_snapshot_meta` 表 | 启动时幂等创建；从 `policy_verify` 回填已核文文号/机关/生效日期；范围确认位默认 false |
| `qa_turn` 状态 | accepted → preparing → validating → 终态；preparing 真实落库 |

不变量：模型不计算、不生成引用、不改结论；判等只由 `triage.py` 完成；审计表 append-only；任何接口不得接收或保存个人原文作为规则真值。

## 5. 实施步骤

1. 后端状态机与租约：`qa_sessions.py`、`qa_routes.py`。
2. 事实锚点与兼容措辞：`provider.py`、提示词自测。
3. handoff 一次消费与进度受控联动：后端 + 三个前端页面 + `main.py`。
4. 政策元数据回填与管理员确认：`qa_evidence.py`、`qa_routes.py`、`main.py`。
5. UI 状态与可访问性：`qa.html`、`qa-workbench.js`、`style.css`、`qa-workbench-polish.css`。
6. 测试补充与全量回归：`tests/test_qa_workbench.py`、`tests/qa_workbench_flow.py`、`tests/smoke.py`。
7. 验证记录写入 `docs/verification.md`。

## 6. 验收标准

| AC | 判定 |
|---|---|
| AC-01 | 新轮次在创建后、证据构建前可观察到 `preparing` |
| AC-02 | 正文锚点缺失、未知、与 claims 不一致时 `validate_fact_consistency` 返回 False |
| AC-03 | 取消后 worker 不再进入模型调用；终态保持 cancelled，槽位归还 |
| AC-04 | 租约在准备与生成阶段刷新；只读接口不改变轮次状态 |
| AC-05 | 同一 handoff 第二次创建任务返回 409；他人 handoff 返回 404 |
| AC-06 | 进度 handoff 只能定位本人 task_id；他人任务不可定位 |
| AC-07 | 已有核文记录回填到快照元数据；范围未确认时证据仍为 needs_verification |
| AC-08 | 咨询页状态区可播报阶段变化；正文区 aria-busy；错误 role=alert |
| AC-09 | 任务状态字典与其余学生页一致 |
| AC-10 | 新增与既有自动用例全部通过；未执行的外部项明确 NOT_RUN |

## 7. 剩余外部阻塞

- 在线模型 50 题回归、人工语义签认、学生实操：NOT_RUN，发布门禁未通过前不宣称在线能力达标。
- 政策“适用范围”确认位需资助管理人员通过新接口显式提交；未提交前保持待核实文案，不由系统推断。
