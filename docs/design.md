# 系统设计

状态：草稿。目标与范围引用 `docs/project-brief.md`，不复制成另一套事实。

## 用户任务与功能分工

用户目标（判断能申请什么）→ 所需依据（政策条款 + 原子条件）→ 系统能力（条款库检索 + 规则判等 + 引用拼装）→ 输出（三档结论 + 依据条款 + 材料清单）。

模型只在两处出现：①把结构化结论组织成学生看得懂的解释文案；②政策问答中的语言理解与表达。**判等、引用拼装、权限、状态全部由程序完成。**

## 主流程

1. 学生填写原子条件字段（可跳过，跳过即 `need_check`）。
2. 系统读取当前 `policy_version` 的条件表达式，逐项确定性判等。
3. 命中项拼装依据条与材料清单；未命中项给线下渠道。
4. 学生确认并提交复核（首版可只读展示，复核为二期接入）。
5. 辅导员复核／驳回 → 学生可申诉 → 改判落 `amended` 并保留原结论。
6. 失败与恢复：检索或模型不可用时降级为规则引擎 + 静态条款直读，页面标"离线模式"，流程不中断。

## 数据与职责

政策原文与文号：官方文件，系统只读存档，版本发布时快照。条款与原子条件：系统维护的事实来源。学生情况：只在任务内使用，脱敏存储。结论与依据条：程序计算得出，可复算。解释文案：模型生成，必须挂 AI 标识。复核与申诉：人工决定，留痕。

## 模块与接口

| 模块 | 职责与边界 | 输入／输出 | 依赖 | 数据拥有者 |
|---|---|---|---|---|
| 政策库与版本发布 | 入库、切块、版本快照、回滚；不做判定 | 政策文件／版本记录 | 存储 | 政策库管理员 |
| 条件原子化 | 条款→原子条件→字段映射；模型可辅助抽取，结果须人工确认 | 条款文本／条件表达式 | 政策库 | 政策库管理员 |
| 规则判等引擎 | 依表达式确定性判等，输出三档结论；不调用模型 | 字段值 + 表达式／结论条目 | 条件库 | 系统（程序） |
| 依据条与材料清单 | 由检索结果与项目配置拼装引用，可回点原文 | 结论条目／引用行 + 清单 | 条款库 | 系统（程序） |
| 政策问答 | 检索 + 引用 + 拒答；无依据明确说不知道 | 问题／答案 + 引用 | 检索、模型 | 系统（程序） |
| 复核与申诉 | 状态机 + checkpoint + 审计 | 结论条目／复核结果 | 任务表 | 辅导员／资助中心 |
| 工作台与看板 | 批量初判、事件计数、口径标注（二期） | 名单／指标 | 任务事件表 | 资助中心 |

## 技术选择

沿用开发规划第 2 章：FastAPI + SQLAlchemy async、PostgreSQL 17 + pgvector、Redis、Vue3 + Element Plus + ECharts、Docker Compose；LLM 三态 Provider（真实／离线规则／Mock）；本地 ONNX bge-small-zh-v1.5。**该选择尚未经实验验证，P3 完成前不作定稿**，重大长期取舍才写 `docs/adr/`。

## 横切要求

权限四档（学生／辅导员／村干部／资助中心管理员）按最小可见原则；敏感字段脱敏且不导出明细；运行日志不记家庭情况；审计表只追加不删除；演示环境只用合成样例。
