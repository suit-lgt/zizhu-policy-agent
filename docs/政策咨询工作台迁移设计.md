# 政策咨询与办理工作台：设计迁移

日期：2026-11-08。状态：已实现并完成自动化验证；本文同时保留设计依据与实现边界，不替代初判、复核和政策发布体系。

本次迁移借鉴教研咨询系统的“同源证据、结构化面板、多轮上下文、历史快照与业务行动”方法。沿用本项目 FastAPI＋SQLite＋多页 HTML、Cookie 身份、现有三态 Provider 和四端入口。没有执行业务迁移、数据库写入或部署。

实施依据：[功能规格](../.scratch/policy-consult-workbench/spec.md)；[开发提示词](../prompts/政策咨询工作台开发提示词.md)；[架构决定](adr/0001-policy-consult-workbench.md)。该规格展开原 R-005，并复用 R-003／R-004／R-007／R-010 的边界。

## 1. 要解决的一次用户任务

学生问“助学金怎么申请”后，应能连续问“要什么材料”“认定还没完成怎么办”“接下来在哪里办理”，不必每轮重新描述项目；系统给出可核验条款、需要补充的条件、材料来源和下一步操作。

个人资格问题通过明确的表单确认和确定性初判处理；问答只能解释政策或本人已有初判，不能在自由聊天中自行判等。原三档 eligible／need_check／not_applicable 由规则引擎给出，模型不新增、不修改。

## 2. 当前代码事实与迁移目标

| 方面 | 当前实现 | 迁移目标 |
|---|---|---|
| 问答 | `backend/app/qa.py`：当前／指定发布版快照检索，整句未中后 4/3/2 字滑窗，首批命中即停 | 同一版本下按项目、意图、适用范围召回并排序；低相关命中不硬答 |
| 请求 | `main.py POST /api/qa`，单轮 JSON | 保留兼容入口，新增有归属的会话、轮次和查询上下文 |
| 历史 | `frontend/qa.html` localStorage 最近 6 个问题，点击后重新请求 | 服务器保存脱敏后的轮次、回答、依据与面板快照，历史回看不重新计算 |
| 证据 | hits／citations 带 clause_id、文号、偏移、version_id | 证据集合驱动正文、卡片、引用、导出及下一步，区分政策／校级配置／任务结果 |
| 原文回看 | `GET /api/clause/{id}` 查询当前 policy_clause | 新增版本限定的引用解析；历史轮次不能只拿裸 clause_id 查当前表 |
| 模型 | offline／online／mock；online 完整回答经 validate 后返回 | 保留验证门禁，先确定性 meta，再输出已验证正文的片段 |
| 置信显示 | 命中至少两条即 high | 不把命中数解释成可靠率，显示有依据／需补信息／需核实／未匹配及原因 |
| 初判 | 独立字段表单、六个确定性代理、三档结果 | 咨询只引导进入初判或解释已授权任务，六代理职责不变 |
| 隐私 | 审计调用写问题前 40 字；浏览器历史不分账号 | 新会话链不落家庭原文日志，审计只存事件元数据；旧浏览器历史清除，不无条件导入 |

## 3. 迁移什么、如何适配

| 原设计思想 | 资助场景适配 | 不直接搬用的内容 |
|---|---|---|
| 四问域 | 五类办理意图＋澄清／拒答控制分支 | 市场、课程、教材分类 |
| 右侧分析 | 本轮办理依据卡片 | 招聘热度、课程覆盖率和图表数量 |
| 图谱／课程对照 | 政策条件、原子字段、本人规则结果 | 用模型推断学生真实情况 |
| 同源 evidence | 版本快照条款＋已确认范围＋已授权任务＋有来源的材料配置 | 仅凭“有引用”就认为语义正确 |
| 样本下钻 | 查看本版条款原文、文号和偏移 | 裸 ID 查当前原文替代历史来源 |
| 转方案修订 | 去初判、补充本人资料、查进度、按既有流程复核／申诉 | 对话按钮直接创建正式申请或自动改判 |
| 流式回答 | 校验通过后分块显示＋显式终态 | 未经校验的模型 token 直接向学生显示 |
| 会话持久化 | 本人可见、脱敏、可删除普通会话，业务审计另行保留 | 匿名共享历史与借会话删除审计 |

## 4. 五类意图与输出

| intent | 学生问题类型 | 主要依据 | 右侧内容 | 下一步 |
|---|---|---|---|---|
| policy_scope | 政策条件与适用范围 | 已核文发布条款、范围元数据 | 适用地区／学段／时期、条件说明、依据 | 进入初判／查看条款 |
| benefit_standard | 金额、标准、能否叠加 | 本版条款及有效校级细则 | 标准与单位、适用条件、待核实差异 | 查原文／咨询资助中心 |
| materials | 要准备什么材料 | 条款＋有来源的 material_item 配置 | 必需／按条件／待确认材料，逐项来源 | 查看／导出准备清单 |
| process | 去哪里办、步骤和时间 | 有效办理通知／条款／经确认配置 | 办理步骤、渠道、明确时限或“待确认” | 进入办理页／联系人工 |
| review_progress | 为什么需核实、复核申诉怎么办 | 本人已授权任务快照与对应政策 | 本人结果、缺项、复核状态、政策依据 | 查本人进度／复核申诉入口 |

clarify 是信息不足分支，refused 是无依据、范围不支持或域外分支。按实际内容组织，不能只凭出现“金额”“基金”等字样机械拒答或匹配。

“我能不能申请”触发个人初判引导：未关联任务时不从聊天自动产生三档结论；有关联任务时只解释已存在结果。没有校级期限、档位映射或渠道信息就明确缺失，不能拿国家条款猜学校操作细则。

## 5. 学生端界面

沿用 qa.html 和 style.css 视觉风格，桌面三块区域：

- 左：本人咨询记录、新会话、主题、历史更新时间；会话标题用通用政策主题，不带家庭细节。
- 中：问答、澄清选项、回答模式、引用编号、生成／完成／中断状态。
- 右：“本轮办理依据”，显示范围、政策依据、待补字段、材料、办理步骤、本人任务解释和动作。

窄屏以问答为主，记录用抽屉，依据区在回答下方展开。首屏不堆统计大图；未知块显示可理解的降级，不让整页空白。

面板块建议：scope、policy、conditions、missing-fields、benefit、materials、steps、task-status、evidence、actions、notice、empty。并非每轮全部出现，按意图和已有证据选取。

点击旧回答切换当轮面板；引用点击打开当轮版本原文。可以在旁边提示“已有更新版本”，不静默替换旧内容。

## 6. 统一查询上下文与版本

QueryContext 由程序解析、校验、合并后确定，建议字段：intent、project_codes、region、education_stage、school_id、as_of_date、policy_version、task_id、task_snapshot_id、confirmed_fields、missing_fields、context_source。

- 项目代码和条件字段沿用 data/projects.json、data/fields.json，不建立另一套并行白名单。
- 本轮明确条件优先于历史；继承只限项目、问域和已确认范围，指代不明就澄清。
- 聊天提及的收入、身份或学校只作为待确认线索；不自动写学生资料、不传为规则真值。
- 一般新咨询首个业务轮固定当前发布版；会话内默认继承。发现新发布版时，提示用户显式切换，新的轮次记录新基线，旧轮保留。
- 解释本人任务时以任务锚定版本和其结果快照为准；任务创建时间用于解释当时结果，同时标注“历史结果，不代表当前申请建议”。
- 用户要求现在重新判断，跳至当前版初判并确认字段和授权，不覆盖旧任务。
- 相同发布日期、不同层级不直接采用“最新覆盖一切”。冲突条款由政策管理员维护的适用与替代规则解决；元数据不足则需核实。
- 当前已发布不等于任意日期仍有效。生效、失效和适用范围不明确时，不产生新的个人资格结论。

旧快照缺少生效日期、适用范围或学校等元数据时应标注不完整，不能读取当前草稿来补成历史事实。对历史回看可展示已保存条款；新的适用性判断须先补齐可追溯元数据或明确拒绝下结论。

## 7. 证据契约

EvidenceBundle 是本轮唯一事实输入，面板纯函数消费它，模型只消费其允许公开且最小必要的部分。建议包括：

- context：已解析且确认的范围和版本。
- policy_items：复合证据 ID、version_id、clause_id、doc_id、文号、标题、条款号、逐字引文、偏移、来源链接、范围／有效期的已核验元数据及缺失标记。
- rule_result：可选；来自本人已授权任务，记录 task_id、结果版本、三档结论和理由。模型不得补项目或修改值。
- missing_fields：字典内字段名、为何需要、是否可由学生填写；需要认定／评审的字段不得让学生自填替代。
- materials／procedure／benefit：带 source_type、来源引用、条件、确认状态、配置版本或本轮配置快照；不把操作提示当政策条款。
- scope_status：supported／needs_clarification／needs_verification／no_evidence，附可解释原因。不是通过率。
- warnings、actions、retrieval_trace：缺失、下一步及必要诊断；后台诊断不泄漏给学生。

规则：无条款不生成政策资格／金额／叠加结论，但可以给一般导航或说明“当前未查到”。引用由程序从 evidence 构建，正文编号指向它；数字、截止日和个人结论必须逐项有来源并核对支持关系。下钻使用 version_id＋clause_id 或受控 evidence_id，不能默认使用最新表。

材料来源分“政策明文”“已确认校内要求”“演示配置／待学校确认”。后者不得进入“已完整准备”或“政策必需材料”的断言。材料表当前不是版本快照，本次需要将当轮用到的配置冻结，避免历史清单漂移。

## 8. 多轮、状态与流式

拟新增服务端会话／轮次，SQLite 即可。状态：accepted → preparing → validating → completed；分支 clarified、refused、failed、cancelled、interrupted。completed 表示回答已生成并保存，不表示学生完成申请或获得资格。

推荐协议：meta（已经核验的面板／口径）→ chunk*（通过校验的正文片段）→ citations → done(status,turn_id)。准备失败返回 error＋显式终态；网络断开无终态时前端保持中断／待恢复，按 turn_id 查状态。

当前 provider 为完整生成后 validate，继续保留。在线生成时显示准备进度，不直接转发未验证原始 token；校验通过后分块发送应称“分块展示”，不伪称原生 token 流。离线与 Mock 走同一证据和状态契约。

建议让 POST /turns 创建可幂等恢复的轮次，事件订阅与任务执行解耦；首版可采用同进程轻量任务加数据库状态，无需 Redis。服务重启将未完成轮标记 interrupted，不能保证静默续算；用户重试创建新 attempt 并保留关联。完成结果先落库再发送 done，流断开不决定后台任务必然失败或完成。

## 9. API 与数据设计（已实现）

保留 POST /api/qa 单轮 JSON 接口兼容现有评测，内部复用新证据服务；旧字段保留，不将兼容 confidence 展示为可靠率。

建议扩展：

- POST／GET /api/qa/sessions；GET／PATCH／DELETE /api/qa/sessions/{id}。
- POST /api/qa/sessions/{id}/turns：question、parent_turn_id、可选 task_id、confirmed_context、client_request_id。
- GET /api/qa/turns/{id}：状态及已持久化结果；GET .../{id}/events：SSE 或兼容轮询。
- GET /api/qa/turns/{id}/evidence/{evidence_id}：该轮版本证据；服务端校验会话归属。
- GET /api/qa/sessions/{id}/export?turn_id=...：指定轮；全会话另用 scope=all，缺少两者时不默认越范围。
- POST /api/qa/turns/{id}/handoff：生成最小、可过期、一次消费或幂等的本人办理上下文，不创建正式任务／复核。

数据建议 qa_session、qa_turn、必要 qa_handoff 三张表，字段与约束见功能 spec。新增表在 app.db 中，不将对话塞入政策库。复合唯一 request id 防重试重复创建；事务内短读写，模型调用期间不持 SQLite 写锁。

这些路径是设计约定，不是现有端点。实施时核对 _entry_blocked、反向代理前缀和四端规则：学生端可访问自己的咨询；管理与教师端不因此获得所有私人聊天。前端继续相对 API 路径和 fund_session Cookie，不照搬源系统 Bearer token。

## 10. 隐私、访问与业务联动

新咨询会话只接受真实登录会话，不因旧演示请求头兜底而开放学生历史。初版仅本人可读写；管理／教师查看业务任务按原流程权限，不自动扩展到聊天内容。所有 turn、证据、导出、handoff 入口都验证归属。

默认保存去标识后的问题和回答；姓名、证件、电话、账号等先去除，家庭细节不进入审计或请求日志。在线模型仅接收政策条款、所需问题语义和必要的非识别性已确认状态。若脱敏破坏问题含义，改用澄清／结构化表单，不保存一份所谓原始全文作兜底。

旧 localStorage 历史不自动导入当前用户；升级时清理旧共享键，退出后清空内存。会话删除可删除普通历史内容；已存在的初判、复核、申诉和其最小来源快照不得连带删除，I-5 保持。

转初判：只携带本人确认的 project_code／关注条件名、来源轮次，学生到 triage.html 重新核对数据并勾选 consent。不得用 URL query、localStorage 或日志携带家庭明细。

转进度／复核／申诉：只携带本人 task_id，进入 progress.html，仍使用原有校验和确认动作。咨询导出仅为个人办理参考，不替代材料报送审批、不自动提交任何外部系统。

## 11. 需要显式处理的现有差异

- qa.py 已有版本快照，不能重建另一套未发布库做回答；原文回看却仍查当前表，需要补版本链。
- “≥2 条命中=high”不是事实正确率；按证据状态解释。
- qa_v1 提示词同时写“不替学生判资格”和三档措辞，迁移时明确三档只来自程序已有结果。
- AGENTS I-2 的两种措辞与 CONTEXT／D-011 三档定义不一致，本轮只澄清职责，不改变现有规则结论。
- qa.py 固定免责声明包含全局未核文表述；后续按实际证据状态展示，保留参考用途声明，不把旧历史全局状态当每条证据状态。
- 审计当前写 question[:40]，新咨询链须改为 turn_id／intent／版本／结果状态等元数据，禁止延续家庭细节日志。
- docs/design.md 的旧技术预案不是当前实现；本次不引入 Vue、Neo4j、Redis 或强制 LangGraph。

## 12. 实施边界与顺序

第一阶段：版本证据契约与相关性 → 会话／上下文／隐私 → 确定性办理面板 → 校验后分块展示。
第二阶段：本人初判／进度联动、个人咨询导出与整链验收。

不迁移教研业务指标、不增加自动发放或审批、不自动拓展政策地域／新政策、不中途切换数据库与前端框架、不重做初判六代理。

详见 spec 的 PC-AC 验收和六张任务票。本轮仅完成设计检查；新增接口、UI、模型评测、部署均为 NOT_RUN。
