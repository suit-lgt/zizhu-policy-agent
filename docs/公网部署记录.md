# 公网子路径部署记录

日期：2026-11-07
访问地址：`https://zhigang.suit-achieve.cn/ZizhuAgent/`
部署目录：服务器 `/home/ubuntu/ZizhuAgent`

## 1. 现场情况

- 目标域名已解析到部署服务器（IP 不写入代码仓库），服务器为 Ubuntu 24.04。
- 该域名根路径已有一个在用站点（产教融合智能教学规划系统），由 Caddy 监听 80/443，根站后端在 `localhost:8081`。
- 服务器 8000 已被另一个预览服务占用，8001 已被既有审核服务占用，不能直接沿用本地 8000—8003 映射。
- 服务器已有 Docker 29.8.0 和 Docker Compose，无需安装。

## 2. 部署结构

```text
浏览器
  │  https://zhigang.suit-achieve.cn/ZizhuAgent/...
  ▼
Caddy（80/443，现有根站不动）
  │  handle_path 剥离 /ZizhuAgent 前缀
  │  header_up X-Forwarded-Prefix: /ZizhuAgent
  ▼
127.0.0.1:9100
  ▼
容器 zizhu-agent（镜像 fund-agent:0.6，容器内 8000）
  ├─ /app/backend
  ├─ /app/frontend
  └─ /app/data（挂载 /home/ubuntu/ZizhuAgent/data）
```

公网只暴露一个 HTTP 入口；本地/开发环境仍保留 8000—8003 四端端口设计。公网四类角色通过同一子路径下的 `index.html`、`review.html`、`admin.html` 进入，后端仍按 `fund_session` Cookie 的角色做权限判断。

## 3. 关键改造

- 前端页面内链、样式、接口请求由绝对根路径改为相对路径：
  - `href="/static/style.css"` → `href="static/style.css"`
  - `fetch("/api/...")` → `fetch("api/...")`
  - 页面跳转使用 `index.html`／`review.html`／`admin.html`／`login.html`
- 后端新增 `/index.html` 路由别名，避免登录后落到 404。
- 登录 Cookie 根据 `X-Forwarded-Prefix` 设置 `Path=/ZizhuAgent`，不会把会话发给同域根站；退出时使用同一路径删除。
- Caddy 对 `/ZizhuAgent` 精确 301 到 `/ZizhuAgent/`，其余 `/ZizhuAgent/*` 剥离前缀转发到 9100。

## 6. 运维命令

```bash
cd /home/ubuntu/ZizhuAgent
docker compose -f docker-compose.server.yml ps
docker logs --tail 100 zizhu-agent
docker compose -f docker-compose.server.yml restart
```

更新代码时，在本机构建镜像后导出：

```powershell
docker build --pull=false -t fund-agent:0.6 .
docker save -o fund-agent-0.6.tar fund-agent:0.6
```

压缩上传到服务器后 `gunzip -c ... | docker load`，再 `docker compose up -d --no-build --force-recreate`。

## 7. 回退

- 应用回退：`docker compose -f docker-compose.server.yml down`，或恢复到上一镜像后重新 `up -d`。
- 反向代理回退：`sudo cp /etc/caddy/Caddyfile.bak.20261107-zizhu /etc/caddy/Caddyfile && sudo systemctl reload caddy`。
- 数据回退：使用项目 `backend/scripts/backup.py` 的数据库备份，或从 `/home/ubuntu/ZizhuAgent/data` 的备份恢复。
